# 개발 명세

2026년 10월 30일 · 다연

이 문서는 명세서의 기능 ID(F-, P-, G-, S-)를 그대로 구현하기 위한 결정, 스키마, 계약, 작업 목록이다. 위에서 아래로 따라가면 1단계부터 바로 코딩할 수 있다.

## 1. 확정한 기술 결정

C# WPF 클라이언트 + Supabase 서버로 간다. 둘 다 무료이고, 투명 창과 실시간 중계를 직접 만들지 않아도 된다.

| 항목 | 결정 | 이유 |
|---|---|---|
| 클라이언트 | .NET 8, C# 12, WPF | WPF는 AllowsTransparency와 Win32 interop으로 투명·클릭통과 창을 수십 줄로 만든다. WinUI 3는 layered window 지원이 약하다. |
| 서버 | Supabase 무료 프로젝트 (Postgres + Realtime + RPC) | 표, 실시간 브로드캐스트, 서버 함수가 한 곳에 있다. 서버 코드를 호스팅할 필요가 없다. |
| 클라이언트 SDK | supabase-csharp (NuGet supabase) | 로그인, 테이블 조회, RPC 호출, Realtime 구독 지원 |
| 인증 | Supabase 이메일+비밀번호. 관리자가 대시보드에서 친구 계정을 미리 만들고 비번을 전달. 가입 화면 없음. | auth.uid()로 RPC와 RLS에서 본인 확인이 된다. 토큰은 DPAPI로 암호화해 로컬 저장. |
| 포포 변경 | 클라이언트는 popo_ledger에 쓰기 금지. 모든 변경은 RPC(4절)로만. | RLS로 insert를 막아 친구가 치트 못 하게 |
| 실시간 | 영속 데이터(메시지, 원장, 장착)는 Postgres Changes 구독. 일시 이벤트(던지기, 입력 중, 선물 애니메이션)는 Broadcast 채널 room:main. | 던지기는 DB에 남길 이유가 없다 |
| 접속 상태 | Realtime Presence (room:main) + users.last_seen 60초마다 갱신 | Presence로 즉시, last_seen으로 재접속 시 복구 |
| 렌더링 | WPF Canvas 위에 캐릭터당 Image 1개, DispatcherTimer 33ms (30fps) | 캐릭터 10마리 이하라 충분 |
| 로컬 설정 | `%APPDATA%\PopoWorld\settings.json` | 7절 스키마 |
| 로그 | Serilog → `%APPDATA%\PopoWorld\logs\app-.log` 일 단위 | 친구가 "안 돼요" 하면 파일 받기 |
| 배포 | `dotnet publish -r win-x64 --self-contained -p:PublishSingleFile=true` → exe 하나를 zip으로 전달 | 설치 프로그램·자동 업데이트 없음 |
| 저장소 | GitHub private 1개, 폴더 client/, supabase/ | 2절 |

## 2. 저장소 구조와 프로젝트 설정

프로젝트는 PopoWorld.App(WPF 실행) 하나와 PopoWorld.Core(순수 C#, 물리·검증·모델) 하나로 나눈다. Core에는 WPF 참조가 없어서 단위 테스트가 쉽다.

## 3. DB 스키마

`supabase/migrations/0001_schema.sql` 참고. users.id는 Supabase auth의 사용자 id와 같다.

RLS 요약 (0003_rls.sql)

| 표 | select | insert | update | delete |
|---|---|---|---|---|
| users | 로그인한 모두 | 없음 (관리자가 대시보드로) | 본인 행만, 컬럼은 last_seen(과 name)만 | 없음 |
| messages | 모두 | 본인(user_id = auth.uid()) | 없음 | 없음 |
| catalog | 모두 | 없음 | 없음 | 없음 |
| inventory | 모두 | 없음 (RPC만) | 없음 | 없음 |
| popo_ledger | 본인 행만 | 없음 (RPC만) | 없음 | 없음 |

RPC 함수는 security definer로 만들어 RLS를 우회해 inventory와 popo_ledger에 쓴다. 장착 update는 보유 검사가 필요하므로 이것도 RPC(equip)로 한다.

## 4. 서버 함수(RPC) 계약

포포와 보유를 바꾸는 길은 아래 5개 함수뿐이다. 전부 security definer, 호출자는 auth.uid()로 식별하고, 결과는 {ok, balance, error} JSON 하나로 돌려준다. 실패해도 예외를 던지지 않고 ok=false와 error 코드를 준다.

| 함수 | 입력 | 하는 일 | 거부 코드 |
|---|---|---|---|
| earn(reason text, request_id uuid) | reason ∈ daily_login, message, hit, streak | 한도 안이면 원장에 +delta. 한도는 함수 안에 상수로: daily_login 5/1일, message 1/10일, hit 1/5일, streak 20/7일 | limit_reached, bad_reason, duplicate |
| purchase(item_id text, request_id uuid) | 카탈로그 id | 활성 아이템, 미보유, 잔액 ≥ 가격이면 원장에 −price(reason purchase, ref_id item_id) + inventory insert | not_found, already_owned, insufficient:<n> (n = 부족량), duplicate |
| gift(to_user uuid, amount int, memo text, request_id uuid) | amount ≥ 1, memo ≤ 20자 | 본인 제외, 잔액 ≥ amount, 오늘 gift_out 합 + amount ≤ 30이면 원장 2줄(gift_out −amount, gift_in +amount, 같은 ref_id = request_id) | self, insufficient:<n>, daily_limit, bad_amount, duplicate |
| equip(slot text, item_id text) | slot ∈ character, bubble, ball, chair; chair는 null 허용 | 보유(또는 가격 0)인지 확인 후 users 컬럼 갱신 | not_owned, bad_slot |
| admin_grant(to_user uuid, amount int, memo text) | 관리자만 | reason admin으로 원장 추가 | forbidden |

공통 규칙

- request_id는 클라이언트가 Guid.NewGuid()로 만들어 보낸다. 같은 (user_id, request_id)가 이미 원장에 있으면 duplicate 대신 그 때의 결과를 다시 돌려준다. 버튼 연타와 재시도가 안전해진다.
- 한도의 "오늘"은 (created_at at time zone 'Asia/Seoul')::date = (now() at time zone 'Asia/Seoul')::date.
- 잔액 계산은 항상 balances 뷰. 함수 안에서 select ... for update로 같은 사용자의 동시 호출을 직렬화한다.
- 성공 응답 예: `{"ok":true,"balance":27}`. 실패 예: `{"ok":false,"error":"insufficient:3","balance":7}`.

earn 호출 시점 (클라이언트)

| reason | 언제 |
|---|---|
| daily_login | 로그인 성공 직후 1회. 거부돼도 무시. |
| message | 메시지 insert 성공 직후 |
| hit | throw 이벤트에서 to_id가 나일 때, 공 도착 애니메이션 끝난 뒤 |
| streak | daily_login 성공 후 서버가 연속 7일 여부를 보고 자동 지급하므로 클라이언트 호출 없음 |

## 5. 실시간 채널과 이벤트

채널은 room:main 하나다. 세 가지 방식을 섞어 쓴다: Postgres Changes(영속), Broadcast(일시), Presence(접속).

| 구분 | 이벤트 | 보내는 쪽 | 페이로드 | 받는 쪽 동작 |
|---|---|---|---|---|
| Postgres Changes | messages INSERT | DB | 행 전체 | 말풍선 8초, 미읽음 +1 |
| Postgres Changes | users UPDATE | DB | 행 전체 | 장착 4개 교체, name 갱신 |
| Postgres Changes | popo_ledger INSERT (본인 행만 RLS로 걸러짐) | DB | 행 | 잔액 재조회, reason이 gift_in이면 말풍선 "OO님이 N포포를 보냈어요: 메모" |
| Broadcast | typing | 클라이언트 | `{"user_id":"…","on":true}` | "…" 표시/해제 |
| Broadcast | throw | 클라이언트 | `{"event_id":"…","from_id":"…","to_id":"…","ball_id":"ball_snow"}` | 두 캐릭터의 내 화면 좌표로 궤적, 도착 시 effect 재생, to_id가 나면 earn(hit) |
| Broadcast | gift_anim | 클라이언트(선물 성공 직후) | `{"event_id":"…","from_id":"…","to_id":"…","amount":3}` | 선물 상자 궤적. 잔액·말풍선은 ledger 이벤트가 담당 |
| Presence | track | 클라이언트 | `{"user_id":"…","state":"online"\|"idle"}` | 프레임 전환. leave 수신 시 offline(회색) |

이벤트 JSON 예시

```json
{
  "type": "broadcast",
  "event": "throw",
  "payload": {
    "event_id": "8c1a5f7e-2b43-4d9a-9c0e-5f1a2b3c4d5e",
    "from_id": "a1b2c3d4-…",
    "to_id": "e5f6a7b8-…",
    "ball_id": "ball_tomato",
    "sent_at": "2026-10-30T03:12:45Z"
  }
}
```

중복과 만료 규칙

- 클라이언트는 최근 200개 event_id를 HashSet에 들고 있다가 같은 id가 오면 버린다.
- sent_at이 지금보다 10초 넘게 오래됐으면 재생하지 않는다 (재접속 시 밀린 이벤트 방지).
- typing on은 3초 동안 새 on이 없으면 클라이언트가 스스로 끈다. 보내는 쪽은 1초에 한 번만 보낸다.
- 재접속하면 users 전체와 balances(본인)를 다시 읽고, Presence 상태로 온라인 목록을 다시 만든다.

좌표 계산 (받는 쪽): from_id와 to_id의 캐릭터 중심점을 내 화면에서 찾아 ThrowArc(from, to, duration 0.6s)를 만든다. 둘 중 하나가 내 화면에 없으면(오프라인 숨김 등) 재생하지 않는다.

## 6. 오버레이 창 구현 규격

창은 두 종류다. 큰 표시 창 1개는 완전히 클릭을 통과시키고, 캐릭터마다 작은 핫스팟 창 1개가 따라다니며 클릭·드래그를 받는다. WPF에서는 WindowStyle=None, AllowsTransparency=True, Background=Transparent에 Win32 확장 스타일을 더하면 된다.

| 창 | 크기·위치 | Win32 확장 스타일 (GWL_EXSTYLE) | 역할 |
|---|---|---|---|
| OverlayWindow | 선택한 모니터의 작업 영역을 선택한 변에 맞춰 띠 모양으로. 두께 160px, 길이 = 변 길이 × 영역 비율(1, 1/2, 1/3) | WS_EX_LAYERED \| WS_EX_TRANSPARENT \| WS_EX_TOOLWINDOW \| WS_EX_NOACTIVATE | 캐릭터·말풍선·공 그리기만. 입력 없음. |
| HotspotWindow (캐릭터당 1개) | 캐릭터 스프라이트 크기 + 여백 8px, 매 틱 캐릭터 위치로 이동 | WS_EX_LAYERED \| WS_EX_TOOLWINDOW \| WS_EX_NOACTIVATE (TRANSPARENT 없음) | 완전 투명(알파 1/255)이지만 마우스 이벤트를 받음. 클릭·더블클릭·우클릭·드래그 |

WS_EX_NOACTIVATE를 빼면 캐릭터를 클릭할 때마다 작업 중인 앱의 포커스를 뺏는다. Topmost=True를 켜고, 전체화면 앱이 떴을 때는 숨긴다(GetForegroundWindow의 크기가 모니터와 같으면 전체화면으로 본다, 1초마다 검사).

틱 루프 (30fps, DispatcherTimer 33ms)

1. PresenceService에서 idle 여부 갱신 (GetLastInputInfo, 5분)
2. 캐릭터마다 WalkAgent.Step(dt): 상태기계 idle → walk → idle, 목표 x는 띠 안의 난수, 속도 40px/s, idle 2~6초
3. 드래그 중이면 DragSpring: 마우스 위치를 따라가고 놓으면 감쇠 스프링(강성 120, 감쇠 14)으로 띠 바닥으로 복귀
4. 공·선물 ThrowArc.Step(dt): 포물선, 0.6초, 도착 시 effect와 소리
5. 프레임 인덱스 계산 → Image.Source를 스프라이트 시트의 CroppedBitmap으로 교체 (미리 잘라서 캐시)
6. 말풍선 위치 = 캐릭터 머리 위 8px, 화면 밖이면 반대쪽으로 뒤집기, 겹치면 y를 24px씩 위로
7. HotspotWindow를 캐릭터 위치로 MoveWindow

네 방향 처리: 모든 물리는 "바닥이 아래"인 로컬 좌표(x 진행, y 높이)로 계산하고, EdgeLayout.ToScreen(edge, local)이 마지막에 회전·반사해 화면 좌표로 바꾼다. 스프라이트는 좌·우 변에서 90도 회전된 그림을 쓰지 않고, 좌우 변에서는 캐릭터가 세워진 채로 위아래로 걷는 것으로 한다(좌우 반전만).

DPI: 앱 매니페스트에 PerMonitorV2. 좌표는 전부 물리 픽셀로 계산하고 WPF에 넘길 때만 / DpiScale.

마우스 → 동작

| 입력 | 내 캐릭터 | 친구 캐릭터 |
|---|---|---|
| 클릭 | 입력창 토글 | 공 던지기 (throw broadcast) |
| 더블클릭 | 입력창 열기 | 공 던지기 1회 (더블클릭 두 번째 클릭은 무시) |
| 우클릭 | 메뉴: 상점, 설정, 숨기기 | 메뉴: 포포 선물, 이 친구에게 던지기 |
| 드래그 (4px 이상 이동) | 캐릭터 이동, 놓으면 복귀 | 캐릭터 이동(내 화면에서만), 놓으면 복귀 |

## 7. 에셋 규격과 로컬 설정

캐릭터 하나는 스프라이트 시트 PNG 한 장과 manifest.json 한 개다. 기본 48×48, 화면에는 2배(96px)로 NearestNeighbor 확대해서 픽셀 느낌을 살린다.

시트 규격: 한 줄에 프레임 8개, 줄 순서는 idle, walk, sleep, hit, offline(1프레임, 회색). 오른쪽을 보는 그림만 그리고 왼쪽은 코드에서 반전한다.

```json
{
  "id": "char_penguin",
  "frame": { "w": 48, "h": 48 },
  "anchor": { "x": 24, "y": 46 },
  "head": { "x": 24, "y": 6 },
  "animations": {
    "idle":    { "row": 0, "frames": 4, "fps": 4, "loop": true },
    "walk":    { "row": 1, "frames": 6, "fps": 8, "loop": true },
    "sleep":   { "row": 2, "frames": 2, "fps": 1, "loop": true },
    "hit":     { "row": 3, "frames": 3, "fps": 10, "loop": false },
    "offline": { "row": 4, "frames": 1, "fps": 1, "loop": true }
  }
}
```

anchor는 발 위치(띠 바닥에 닿는 점), head는 말풍선 꼬리가 가리키는 점이다. 공은 16×16 PNG 1장, 말풍선은 9-slice용 32×32 PNG 1장(모서리 8px), 의자는 48×32 PNG 1장과 앉았을 때 캐릭터 y 오프셋 값.

에셋 위치: 기본 캐릭터 3종과 기본 공·말풍선은 exe에 포함. 유료 아이템은 catalog.image_url(Supabase Storage 공개 버킷 assets)에서 첫 사용 시 내려받아 `%APPDATA%\PopoWorld\cache\`에 저장한다.

settings.json (SettingsStore가 임시 파일에 쓰고 File.Move(overwrite)로 교체)

```json
{
  "version": 1,
  "monitor": "\\\\.\\DISPLAY1",
  "edge": "bottom",
```

## 9. 마일스톤별 완료 조건

각 마일스톤은 친구 한 명과 같이 켜보고 아래 항목을 모두 체크하면 넘어간다. M1은 혼자 한다.

M1 혼자 돌아가는 캐릭터 (T-01~T-08)
- [ ] 캐릭터 뒤 빈 공간 클릭이 아래 창으로 간다
- [ ] 캐릭터 클릭 시 작업 중이던 앱의 커서가 안 사라진다
- [ ] 네 변 모두에서 걷고, 드래그하면 복귀한다
- [ ] 트레이 종료 후 작업 관리자에 프로세스가 없다

M2 둘이 대화 (T-09~T-14)
- [ ] 두 PC에서 로그인하면 서로의 캐릭터가 보인다
- [ ] 보낸 말이 3초 안에 상대 화면 말풍선으로 뜬다
- [ ] 201자, 4줄은 보낼 수 없다
- [ ] 앱을 껐다 켜면 로그인 창 없이 들어간다

M3 상태 (T-15~T-16)
- [ ] 앱 종료 30초 안에 상대 화면에서 회색이 된다
- [ ] 5분 방치 후 상대 화면에서 존다
- [ ] 인터넷을 1분 끊었다 켜면 다시 메시지가 온다

M4 던지기 (T-17~T-18)
- [ ] 양쪽 PC에서 같은 사람 → 같은 사람으로 공이 간다
- [ ] 광클해도 초당 2개 이하
- [ ] 음소거 시 소리가 없다

M5 포포 (T-19~T-21)
- [ ] 로그인 2번째에는 daily_login이 거부된다
- [ ] 메시지 11번째는 포포가 안 오른다
- [ ] SQL로 같은 request_id를 두 번 호출해도 원장 1줄

M6 상점 (T-22~T-23)
- [ ] 잔액 7에서 10포포 아이템은 "3포포 부족"이 보인다
- [ ] 사면 상대 화면에서 내 외형이 바뀐다
- [ ] 같은 아이템은 다시 살 수 없다

M7 선물 (T-24)
- [ ] 3포포 보내면 나 −3, 상대 +3, 원장 2줄
- [ ] 오늘 31포포째는 거부된다
- [ ] 오프라인 친구에게 보내면 접속 때 말풍선이 뜬다

M8 배포 (T-25~T-27)
- [ ] exe 하나만 받아서 실행된다
- [ ] 전체화면 게임 중엔 안 보인다
- [ ] 친구 3명이 동시에 쓰고 로그에 Error가 없다
